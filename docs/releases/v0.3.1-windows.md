# Remote VoiceIME 0.3.1 · Windows alpha

构建 11，2026-10-27。Windows 修订版，修复 [0.3.0](https://github.com/jacksonlin-infra/remote-voiceime/blob/main/docs/releases/v0.3.0-windows.md) 在实际使用中发现的投送与语音启动问题。本次发布仅包含 **Windows x64**；macOS 当前发布仍为 [0.3.0](https://github.com/jacksonlin-infra/remote-voiceime/releases/tag/v0.3.0-macos)（共享版本元数据已为 0.3.1 / 11，macOS 未重新构建发布）。

## 修复

- **新连接的 Mac 远端收不到文字。** UU 按设备记住粘贴键；从未设置过的设备此前一律使用 Ctrl + V，Mac 远端不会粘贴，但本机仍显示“已投送”。现在名称像 Mac 的设备（MacBook、MacMini、iMac 等）默认 Win + V；首次投送到未设置过的设备时，底部提示写明所用按键，并可一键“改用 … 重贴”且记住。
- **豆包提示“当前不是豆包输入法”、按右 Ctrl 时好时坏、之后怎么按都不响应。** 浮条是新窗口，此前使用系统默认输入法；豆包只在自己是当前输入法的窗口响应语音键。现在浮条打开时与每次开始录音前自动切换为豆包（只影响本工具，其他应用的输入法不变）。
- **右 Ctrl 传到远端。** 远端窗口里的第一次右 Ctrl 不再交给豆包：它只在 UU 窗口恰好以豆包为输入法时有效，否则会弹出豆包提示、让后续按键失灵，并把 Ctrl 发给远端。现在第一次按键只打开浮条，远端收不到。
- **安装程序覆盖升级。** 刚退出的托盘进程短暂占用旧程序时，静默安装可能保留旧版本却报告成功；现在会等待旧文件释放，无法替换时明确报错。

## 操作变化

UU 与远程桌面统一为三次按键：

1. 在远端输入框放好光标，按 **右 Ctrl**：打开浮条。
2. 再按 **右 Ctrl**：豆包开始录音，说话。
3. 说完按 **右 Ctrl**：结束并自动投送。

豆包无响应约 1 秒时浮条提示再按一次，并重新选中豆包；诊断记录当时的输入法与豆包窗口状态。

## 下载与校验

| 文件 | 用途 |
| --- | --- |
| `RemoteVoiceIME-0.3.1-win-x64-setup.exe` | 安装程序（推荐，可直接覆盖 0.3.0） |
| `RemoteVoiceIME-0.3.1-win-x64.zip` | 免安装版 |
| `SHA256SUMS.windows-win-x64.txt` | SHA-256 校验 |

安装前从托盘退出旧版本。安装后在「设置 → 运行环境与诊断」底部核对 **0.3.1（构建 11）**。安装程序与程序均未做发布者代码签名，SmartScreen 可能提示未知发布者。目标为 Windows 10 / 11 x64，内置 .NET 运行时；只为当前用户安装，无需管理员权限，设置沿用。

## 验证范围

- 用户在本机实测 UU 远程（Mac 远端）与远程桌面（mstsc）的三次按键听写与投送，确认均可用。用户实测的构建与发布构建源码相同，仅版本号由 0.3.0（构建 10）改为 0.3.1（构建 11）。
- 139 项 Windows 核心检查、原生 UI 预览明 / 暗各 90 项、输入法切换自检（从英文键盘切回豆包）通过；真实剪贴板自检每轮恢复成功，但本机 UU / Deskflow 剪贴板同步使部分轮次的最终比对失败，最后一次运行全部通过；安装程序的全新安装、覆盖升级、占用时报错与卸载已在本机验证。
- 未验证：Windows 11 Home 另一台机器上的复测、试一次两条路径与准备清单首次运行等逐项场景、真实高 DPI 与多显示器、Deskflow、全屏。

## 已知限制

- 比 0.3.0 设想的 UU 两次按键多一次：Windows 无法只把按键交给豆包而不交给远端，也无法可靠判断 UU 窗口当前的输入法。
- 投送没有远端回执：“已投送”表示本机已发出粘贴键。
- 豆包行为（录音条、组字、输入法提示）基于豆包 v0.9.2.7 实测，豆包升级后需重测。
