# 架构说明

本文面向想阅读或修改源码的贡献者，说明两端原生实现的结构、关键约束和扩展方式。构建与提交流程见 [CONTRIBUTING.md](../CONTRIBUTING.md)；使用方法见[项目首页](../README.md)。

## 整体流程

```text
本地快捷键（右 Ctrl）
  → 捕获会话：打开本地浮条，启动语音来源（豆包）
  → 豆包把识别文字写入浮条（输入法组字 / marked text）
  → 停止录音、等待定稿
  → 投送队列：备份剪贴板 → 写入正文 → 等待同步 → 切回原远控窗口 → 发送粘贴键
  → 远控软件把剪贴板同步到远端，远端输入框收到整段文字
```

工具本身不录音、不识别、不联网。它只做三件事：**用快捷键协调语音来源**、**在本地接收识别文字**、**通过剪贴板 + 粘贴键把文字投送到原远控窗口**。

两端各自原生实现，不共享运行时代码，但遵循同一套阶段、规则和用户可见行为：

| 平台 | 语言 / 框架 | 源码 | 逻辑测试 |
| --- | --- | --- | --- |
| macOS | Swift 5 / AppKit，无第三方包 | `src/` | `tests/main.swift`（`./scripts/test.sh`） |
| Windows | C# / .NET 10 / WinForms | `windows/Bridge.Core`（可移植逻辑）、`windows/Bridge.Windows`（原生适配） | `windows/Bridge.Core.Tests`（`./scripts/build-windows.ps1`） |

共享的产品名、版本与构建号在 `resources/Product.props`，两端构建、界面和打包都从这里读取。

## 捕获会话

捕获阶段依次为 `starting → listening → settling`，异常或需要人工核对时进入 `review`。

- 每个会话有唯一 ID；取消后 ID 失效，过期的启动、探测、停止回调不能修改新会话。
- 自动投送需同时满足：正文非空、没有未完成的输入法组字、录音已确认结束、正文稳定一段时间（macOS 180 ms，Windows 约 0.5 秒）。
- 正文含换行、制表符等控制字符，或超过 64 KiB 时，不自动投送，展开为核对卡片：Return 换行、Esc 取消、右 Ctrl 投送。
- 停止后 2.5 秒仍无文字且豆包已结束：提示“没有识别到文字”并交还焦点。定稿超过 30 秒转为核对，正文保留。
- 取消只影响本轮；若豆包仍在录音，等其结束后再继续之前排队的投送，8 秒仍无法确认则停止并保留到最近文字。

相关代码：macOS `src/Session.swift`（`CaptureSessions`、`TextPolicy`、`SettleRule`）、`src/VoiceApp.swift`；Windows `windows/Bridge.Core/Capture.cs`、`windows/Bridge.Windows/BridgeApp.cs`。

## 投送队列

投送任务持有不可变的正文副本，与浮条中后续编辑无关。队列串行占用剪贴板，最多三条待发；正在听写时不抢焦点执行下一条。

投送前检查按 40 ms 间隔轮询，**全部满足**才发送粘贴键：

1. 已等待所选同步时间（快速 180 ms / 标准 0.5 秒 / 兼容 1.2 秒；Windows 远程桌面固定 0.3 秒；久未使用后的第一条至少 0.8 秒）；
2. 原远控窗口仍有效，回到前台并稳定 0.1 秒；
3. 修饰键已松开；
4. 剪贴板仍是本条正文。

同步时间到后最多再等 1.5 秒；仍不满足就停止、保留文字，并在诊断中记录卡在哪一项（`focus` / `window` / `modifiers` / `clipboard`）。

剪贴板规则：

- 写入前完整备份所有可读格式（上限 16 MB），无法完整备份的内容（如仅有位图句柄）拒绝覆盖。
- 远控把**相同文本**重新发布到本机剪贴板，视为正常；内容变了且任务开始后用户没有键鼠操作，重新写入一次并重新计时；再次变化即停止。用户自己复制的新内容不会被覆盖。
- 默认投送后保留听写文字；选择“恢复原内容”时，只在剪贴板仍属于本次写入时恢复。
- 工具自身发出的按键带标记，不计为用户操作。

结果只有“已发出粘贴键，远端未确认”。**不做自动重发**，用户通过“再贴一次”或最近文字手动重投；重投用新任务替换原记录，避免重复。

相关代码：macOS `src/Delivery.swift`、`src/Clipboard.swift`、`src/DeliveryDiagnostics.swift`；Windows `windows/Bridge.Core/Delivery.cs`、`windows/Bridge.Windows/ClipboardBridge.cs`、`Keyboard.cs`。

## 平台差异

### macOS

- **快捷键**：`RightControlShortcut` 在独立线程的事件 tap（`EventTapThread`）中识别单独轻按右 Ctrl，松开时触发；组合键与 Ctrl＋点击保持原行为。长按约 0.6 秒为“重贴上一条”。
- **启动豆包**：不合成按键，而是通过辅助功能（AX）执行输入法菜单中的“语音输入”，用 TIS 检测和选择豆包输入源（`DoubaoSource`）。
- **远控客户端**：`UURemoteAdapter`、`WindowsAppAdapter` 绑定对应进程及 AX 窗口，发键前重新核对。
- **权限**：辅助功能、输入监控；不申请麦克风、屏幕录制。

### Windows

- **共享物理按键**：豆包只接受真实键盘事件，合成的启动键会被忽略。因此推荐让工具快捷键与豆包语音键都设为右 Ctrl：低级键盘钩子只观察按键、按需放行，同一次物理按键同时被工具和豆包使用。
- **三次按键**：豆包只在自己是当前输入法的窗口响应语音键，所以第一次按键只打开浮条（不交给豆包、不发往远端），浮条通过 TSF 把本进程切换为豆包；第二、三次按键分别开始和结束录音。
- **路由**：`CaptureShortcut.Route`（`Bridge.Core/Capture.cs`）按“是否有会话 / 浮条是否前台 / 原远控窗口是否前台”决定打开、推进、唤回或忽略，以及是否把按键放行给豆包。
- **录音状态**：通过豆包录音条窗口是否可见判断录音开始 / 结束（`DoubaoProbe`），这是基于当前豆包版本的观察，不是公开接口，豆包升级后需复测。
- **远程桌面（mstsc）**：RDP 转发硬件扫描码，粘贴键需填入扫描码；mstsc 会安装自己的键盘钩子，工具在其窗口前台时定期重新注册钩子。
- **粘贴键**：UU 连接 Mac 远端时 Win 映射为 ⌘，需发送 Win＋V；按 UU 设备分别记住。
- **焦点交接**：后台进程激活窗口受前台锁限制，使用 `AttachThreadInput` 交接；激活结果本身不作为失败条件，由投送前检查等待窗口回到前台。

## 扩展方式

两端都按适配器隔离语音来源与远控客户端，避免把某个客户端的特例写进通用捕获和投送逻辑。

| 扩展 | macOS | Windows | 需要实现 |
| --- | --- | --- | --- |
| 新的语音来源 | `VoiceSourceAdapter` | `IVoiceSourceAdapter` | 可用性检测、启动、**可靠停止**、取消，以及录音中 / 已结束 / 未知的状态探测。不能只替换一个进程名 |
| 新的远控客户端 | `RemoteClientAdapter` | `IRemoteClientAdapter` | 识别前台客户端、捕获不透明的目标窗口、发键前重新核对；再实测剪贴板同步时间、粘贴键和焦点行为 |

系统行为（剪贴板、发键、时钟）通过接口注入：macOS `ClipboardAccess` / `PasteEmitter` / `WorkScheduler`，Windows `IClipboardBridge` / `IPasteEmitter` / `IClock`。逻辑测试使用虚拟时钟和测试替身，不访问真实剪贴板、不发键、不真实等待。

## 配置与诊断

| | macOS | Windows |
| --- | --- | --- |
| 设置 | 用户默认设置（Bundle ID 为历史兼容值 `local.jackson.UURightOptionVoice`） | `%LOCALAPPDATA%\RemoteVoiceInput\settings.json` |
| 诊断 | 仅在内存中，设置 → 权限与诊断 → 复制诊断 | `%LOCALAPPDATA%\RemoteVoiceInput\diagnostics.log`，最近 300 行，每次启动覆盖 |

诊断只含元数据（阶段、检查结果、按键扫描码、字数与耗时），**不得记录正文、剪贴板内容或窗口标题**。修改诊断时请保持这一约束。

Bundle ID、Windows 单实例标识和 `RemoteVoiceInput` 目录名沿用旧名，以保留旧配置和系统权限，请勿改动。

## 自检与界面预览

| 命令 | 作用 |
| --- | --- |
| `./scripts/test.sh` | macOS 构建并运行逻辑测试（虚拟时钟、测试替身） |
| `./scripts/test.sh --native-clipboard` | 额外运行真实剪贴板检查 |
| `./scripts/preview.sh` | 离屏渲染 AppKit 界面到 `docs/assets/` 并检查布局与交互 |
| `./scripts/build-windows.ps1` | Windows 核心逻辑测试 + 发布构建（`test-windows.sh` 在 Mac 上只能跑到首个调用 Windows API 的检查） |
| `Remote VoiceIME.exe --preview-ui <目录> [light\|dark]` | Windows 原生界面渲染与检查 |
| `Remote VoiceIME.exe --verify-clipboard <目录>` | Windows 真实剪贴板备份 / 写入 / 恢复自检 |
| `Remote VoiceIME.exe --verify-ime <目录>` | Windows 浮条切换豆包输入法自检 |

自动检查不能替代真实远端验收：涉及快捷键、输入法、剪贴板或焦点的改动，需要在真实的豆包 + 远控软件环境中实测，并在 PR 中写明环境和结果。
